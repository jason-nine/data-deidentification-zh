# Feature Specification: 简体中文 / 中国大陆规则适配

**Feature Branch**: `009-zh-cn-rules`

**Created**: 2026-10-21

**Status**: Implemented

**Input**: 将上游 `dean9703111/data-deidentification`（繁体中文、台湾规则）改造为面向中国大陆用户的简体中文版本：规则数据化、删除台湾规则、内置行政区划仅省＋市、增加 GB18030 文本解码、示例/fixtures/SEO 文档全部大陆化，并部署到自定义域名。

## 1. 背景与目标

上游工具的规则、字典与文案全部建立在台湾语义上（身份证 `[A-Z][12]\d{8}`、手机 `09` 开头、8 位统一编号、县市地址锚点、民国年、`chi_tra` OCR、Noto Sans TC 字体）。直接做「繁体→简体」字形转换会让姓氏表、停用词、地址锚点、公司后缀大面积失效。本规格把规则层重写为中国大陆规则，并把界面与文档整体简体化。

## 2. 范围

### 2.1 规则层（17 类内置类别）

| 类别 | 规则要点 | 校验 |
|------|----------|------|
| 姓名 | 简体常见姓氏（含复姓）＋1–2 字名 | 强弱两档结尾证据（文本边界／称谓／谓语 vs 单个虚词）、名词后缀字否决、停用词表、地名词干、称谓、三字名后两字常用词兜底 |
| 居民身份证号 | `\d{17}[\dXx]`、`\d{15}` | GB 11643 加权 11 校验位 + 出生日期段合法性；15 位旧证只验日期 |
| 手机号码 | `1[3-9]\d{9}`，支持 `138-1234-5678`、`+86`、空格分组 | 前后不得紧邻数字 |
| 固定电话 | `010`／`02x`（3 位区号）、`0[3-9]xx`（4 位区号）＋7–8 位本地号；支持 `+86 10 …`（省前导 0） | 区号位数与本地号位数匹配 |
| 地址 | 省／市／区县锚点＋乡镇街道＋路街巷＋门牌 | 省级行政区名锚定，末尾须为门牌或村名 |
| 邮箱 | 标准格式 | — |
| 单位名称 | 有限责任公司／股份有限公司／集团有限公司／分公司／支行／事务所／合作社／研究院／医院／学校… | 排除本公司／贵公司／该公司／子公司 |
| 统一社会信用代码 | 18 位，字符集 `0-9A-HJ-NPQRTUWXY` | GB 32100 加权模 31 |
| 银行卡号 | 16–19 位，可含空格／连字符 | Luhn + 银联（62）等 BIN |
| 车牌号 | 省简称＋`[A-HJ-NP-Z]`＋5–6 位 | 字母位与数字校验 |
| 护照号 | `E/G/D/S/P`＋8 位 | 必须标签锚定 |
| 国际电话 | `+` 国码号码、北美格式 | libphonenumber-js；`+86` 归手机／固话 |
| 信用卡号（境外） | 13–19 位 | Luhn + 发卡行号段 |
| 美国 SSN | `123-45-6789` 等 | 排除无效区码／组码／序号 |
| IBAN | 可分组空白 | mod-97 + 国家长度 |
| IPv4／IPv6 | 标准写法 | 段范围、URL 解析、排除时间与 MAC |
| 出生日期 | DOB／Date of Birth／出生日期／生日 等标签后 | 支持 `YYYY-MM-DD`、`YYYY.MM.DD`、`YYYY年M月D日`、`YYYYMMDD`；删民国年 |

### 2.2 部分保留（retention）

姓名保留姓；身份证前 2 位（省级）；手机前 3 位（号段）；固定电话区号；地址保留到省或省＋市；邮箱域名；单位名称保留组织形式；银行卡／信用卡后 4 位；车牌省份简称；IBAN 国别码；IP 前两段；出生年份；统一社会信用代码、SSN、护照号全部隐藏。

### 2.3 非规则层

- OCR 语言包 `chi_tra` → `chi_sim`（`src/formats/ocr.ts`、`vite.config.ts`）。
- PDF 内嵌字体 `NotoSansTC-Regular.ttf` → `NotoSansSC-Regular.ttf`。
- 纯文本读取改用 `decodeText`，自动识别 UTF-8 与 GB18030（含 GBK／GB2312）。
- 示例、fixtures、扫描样本、OG 图、截图全部改用大陆数据与简体文案。
- `index.html`（lang、标题、描述、关键词、JSON-LD、FAQ）、`README.md`、`public/llms.txt`、`sitemap.xml`、`robots.txt` 大陆化。

### 2.4 部署

- 站点地址不写死在仓库里，由构建时的 `SITE_URL` 环境变量注入：`index.html`、`sitemap.xml`、`robots.txt` 使用 `__SITE_URL__`／`__SITE_ROOT__` 占位，由 `vite.config.ts` 的 `siteUrl()` 插件替换。未设置时退化为相对引用，并删掉 `sitemap.xml`、去掉 `robots.txt` 的 `Sitemap` 行。
- 不使用 `public/CNAME` 与 `package.json` 的 `homepage`：前者只对 GitHub Pages 有意义，后者会把地址带进公开仓库。
- `vite.config.ts` 保持 `base: './'`，兼容根域名、子路径与 `file://` 打开。

## 3. 关键决策

1. **路线 A（单语简体替换）**：规则与字典抽到 `src/core/rules/`（纯数据），引擎只做组装；不保留台湾规则。
2. **行政区划仅省＋市（366 条）**：区县不内置，短地址由「区／县＋路／街＋门牌」结构兜底，控制体积。
3. **GB18030 支持**：解决大陆用户 GBK 文本乱码的真实痛点。
4. **校验优先**：身份证、统一社会信用代码、银行卡、车牌、护照均以校验码或标签锚定压低误判。
5. **姓名误判兜底**：新增「三字名 = 单姓 + 双字常用词」判定（如「包服务」「高温度」），并补充「服务」「外包」等停用词。
6. **姓名规则改为「强弱两档结尾证据」**（实测反馈后的收紧，见 3.1）：只按姓氏表匹配会把「房屋」「项目」「管道」「权属」「关于」「施工」「形成」这类「姓氏字开头的常用词」全部命中，两字误判尤其密集。现在要求名字必须真正走到词尾或谓语前，并增加名词后缀字否决层。

### 3.1 姓名规则收紧（2026-10-22）

**问题**：原实现有两条分支，一条是「姓 + 1–2 字 + 后接词」，后接词里含 `有／的／在／于／要／称` 等高频单字；另一条是「姓 + 恰好 2 字」不要求后接词。前者让「房屋有」「项目在」「关于要」命中，后者让「权属意见」「管维修养护」「形成水渍」命中——在物业维修函里一次就误判十几处。

**改法**：

| 层 | 规则 | 挡住的例子 |
|---|---|---|
| 结尾证据（强） | 文本边界（结尾／空白／标点／数字／ASCII）或两字以上称谓、谓语（先生、经理、表示、负责、身份证…） | — |
| 结尾证据（弱） | 单个虚词（于、在、的、与、来…），**只给三字名与复姓** | 房屋有、项目在、关于要 |
| 名字用字 | 「名」的部分含名词后缀字（人、产、部、属、内、等、的、被…）即否决 | 所有权人、房地产、项目部、房等专、两小时内、生成的 |
| 停用词表 | 扩充到物业／法律文书高频词（房屋、管道、权属、施工、成果、商祺…） | 房屋，、成果（ |

两字名只认强证据是关键取舍：两字名 + 单个虚词 = 「两字常用词 + 虚词」，几乎必然误判；而三字名（姓 + 双字名）本身足够独特，可以放宽到单个虚词，从而保住「陈大文于」「王小明来电」这类真实写法。

**效果**（`tests/unit/zh-name-context.test.ts` 固化）：

- 用户报告的物业维修函：改动前命中十余处常用词，改动后 **0 误判、2/2 召回**（只留「李建华」「王秀兰」）。
- 全仓库语料（示例文档、测试样本、合同／报价单生成器）：姓名命中从 **181 处 / 68 个去重** 降到 **87 处 / 28 个去重**，剩余全部是真实姓名；唯一像误判的「华路」（新华路）被地址规则以最长匹配覆盖，实际不出现。
- 测试：**386 / 386 通过**（新增 21 条姓名上下文用例）。

## 4. 验证

- 单元 + 集成测试：**386 / 386 通过**（32 个测试文件）。
- 集成覆盖：TXT／DOCX／XLSX／PDF 去标识化 → 还原逐字符 round-trip、真实合同／报价单／60 条客户数据完整性、扫描件 OCR（≥ 90% 预置值命中）、三种标记方式、批量 ZIP、零残留。
- OCR 基线（`npm run eval:ocr`，chi_sim）：主示例字符召回 **98.6%**／精确 98.5%，印刷值 125/144、手写值 10/13、误判 21，图片 4/4、线段 66/66、底色 18/18、复选框 6/6、文字重叠 0；角度样本（3°／6°／90°／180°）字符召回 97.2%–97.6%。
- 构建：`npm run build` 通过（tsc + vite）。
- 素材：`npm run og`、`npm run screenshots` 已用大陆数据重生成。

## 5. 已知限制

- 中文姓名与地址无法做到零误判／零漏抓，界面保留人工复核流程与提示。
- 英文姓名与地址仍无内置规则，需框选新增或自定义正则。
- 行政区划不含区县表，短地址依赖结构兜底。
- 扫描件 OCR 对手写、模糊内容仍可能误认，需逐页核对。
